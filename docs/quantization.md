# 양자화 레시피 — 왜 이 설정인가

이 문서는 **export 시점에 고르는 값**만 다룬다. 기기에서 잰 런타임 결과(기법별 AL·속도, 백엔드
비교)는 MobiSpec.cpp의 `docs/results/qnn_quantization_playbook.md`가 원본이다.

---

## 배포 설정 (2026-09-03 — 드래프트 4비트로 전환)

| | **타깃** Qwen3-4B/8B | **드래프트** DFlash/DSpark-b7 |
|---|---|---|
| 레시피 클래스 | `Qwen3_4B_SqnrQuantRecipe` / `Qwen3_8BQuantRecipe` | **`Qwen3_DFlashDraftW4A16QuantRecipe`** |
| 기본 dtype | `use_16a4w` | **`use_16a4w`** (이전 `use_16a8w`) |
| 활성 | 16비트 per-tensor | 16비트 per-tensor |
| 관찰자 | `MinMaxObserver` | **`MarginMinMaxObserver` (min/max ×2)** |
| 가중치 | **4비트 per-block-16** (LPBQ) + 13그룹 8비트 승격 | **4비트 per-block-16** (이전 8비트 per-channel) |
| LM 헤드 | 8비트 per-channel | 8비트 per-channel |
| KV 캐시 | 8비트 | 8비트 |
| 토큰 임베딩 | 그래프 내부 | **그래프 밖 · 호스트 fp16 mmap** |
| 회전 | R3 (Q·K Hadamard) | 동일 |
| `prefill_ar_len` | 32 | 8 (블록), `n_inject` 16 |
| 컨텍스트 | 4B 3.6 GB · 8B 5.5 GB | **4B 671 MB · 8B 1.2 GB** |

등록명: `qwen3-4b-dflash-w4` · `qwen3-4b-dspark-w4` · `qwen3-8b-dflash-w4` · `qwen3-8b-dspark-w4`.

**4B에서는 최적화, 8B에서는 필수조건이다.** 4B는 수용 1.4~2.8%를 내주고 드래프트 호출 20~24%를
얻어 순 +2.0~+3.6%. 8B는 8비트 드래프트가 5.5 GB 타깃 옆에서 적재되지 않고 기기를 재부팅시킨다.

타깃의 8비트 승격 그룹: `w2` 전 층(0–35), `wv` 7–35, `wo` 21–35, `w3` 7–13 (+544 MiB).
**타깃 레시피는 바뀌지 않았다.**

## 1. 드래프트가 고장났던 이유는 클리핑이다

초기 드래프트는 기기 AL 1.03이었다. 양자화를 두 성분으로 쪼개 각각만 남겨 실행하면 원인이 한
줄로 나온다(층 0 어텐션 경로, 25노드 대상):

| 처리 | L4 잔차 cos | top-1 |
|---|---:|---:|
| 그대로 | 0.7903 | 0/8 |
| **클리핑만 유지**(반올림 제거) | **0.7866** | **0/8** |
| **반올림만 유지**(클리핑 제거) | **0.9911** | **5/8** |

잘리는 원소는 전체의 **0.002%**뿐인데 그것들이 어텐션을 결정하는 극단값이다.

### 범위 여유 스윕 — ×2가 답

| 배율 | L4 cos | top-1 |
|---|---:|---:|
| ×1 (기본) | 0.7866 | 0/8 |
| ×1.5 | 0.9880 | 3/8 |
| **×2 (채택)** | **0.9910** | **6/8** |
| ×4 | 0.9483 | 3/8 |
| ×8 | 0.8348 | 1/8 |

×4를 넘으면 이번엔 반올림 오차를 돌려받는다. `MarginMinMaxObserver`는 `MinMaxObserver`를 상속해
`calculate_qparams`에서 min/max에 배율을 곱하는 20줄이다(`static_llm_quant_recipe.py`).

⚠️ **`HistogramObserver`는 악화시킨다**(1/8 → 0/8). MSE 최소화가 범위를 *좁히는* 쪽이라 고장
방향과 정확히 반대다. "더 정교한 관찰자"라는 직관이 여기서는 틀린다.

## 2. 드래프트 설정 전수 시도

| 설정 | 결과 | 판정 |
|---|---|---|
| 16a8w MinMax | top-1 1/8, 기기 AL 1.03 | 실패 |
| + 캐시 채운 캘리브 | 1/8 | 무효과 |
| + mask-token 블록 캘리브 | 1/8 | 무효과 |
| + `HistogramObserver` | 0/8 | 악화 |
| + SmoothQuant α=1 폴딩 | cos 0.819 → 0.464 | 악화 — 스케일 축이 `fc`의 *입력* 채널인데 가중치 양자화는 *출력* 채널을 따라 돈다 |
| `fc` per-channel | 양자화기 거부 | 불가 — "Unsupported per channel quantization axis: None" |
| **+ 여유 ×2 (배포)** | **6/8, 기기 AL 3.62** | **채택** |
| w4a16 + 여유 ×2 | 동률, 컨텍스트 1.60 → 1.38 GB | 살아 있는 카드 (8B 페어에서 값어치) |
| w4a8 + 여유 ×2 | L4 0.1724, AL 1.04, 0.66×AR | 붕괴 — 활성 8비트는 이 드래프트에 너무 거칠다 |

**가중치만 격리한 상한**(활성 무손실): 16b 1.0000 / **8b 0.9976** / 4b-block16 0.8426 /
4b-block32 0.8186 / 4b-per-channel 0.6329. 4비트에서는 **입도가 폭만큼 중요하다**.
`QUANT_CONFIG_DICT`에 `8a4w`의 per-block 항목이 없어서 활성 8비트를 쓰면 4비트 가중치가 자동으로
약한 per-channel로 떨어진다 — w4a8 붕괴에 이것도 겹친다.

## 3. 호스트 임베딩 테이블 정밀도

| 테이블 | 로짓 cos | top-1 | 크기 |
|---|---:|---:|---:|
| GGUF Q4_0 (기보유) | 0.9371 | 3/8 | 219 MB |
| Q8_0 | 0.9998 | 7/8 | ~401 MB |
| **fp16 (채택)** | **1.0000** | **8/8** | 742 MiB |

생성은 `scripts/dump_draft_embd.py`. mmap이라 상주 페이지는 스텝당 8행뿐이다.

**속도 이득은 없다.** 컨텍스트에서 724 MB를 빼도 드래프트 호출이 16.4 → 17.8 ms로 오히려 늘었다.
`18 ms/GB` 비용모델은 매 호출이 곱해 쓰는 **밀집 가중치에만** 적용되고 조회 테이블에는 적용되지
않는다 — QNN은 gather가 건드리는 행만 읽는다. 밀집 가중치를 4비트로 내리면 16.4 → 13.8 ms.

## 4. `ar_len` 확장은 손해다

`prefill_ar_len=64`로 재export해 같은 B=31을 두 컨텍스트에서 재면 트리 효과가 상쇄되고 그래프를
넓힌 대가만 남는다: NPU 드래프트 −4.0~−7.2%, GPU 드래프트 −13.3~−17.8%. `ar_len=32`가 옳다.

## 5. 커스텀 기법을 넣을 자리

QNN 기본 레시피 밖으로 나갈 수 있는 지점은 네 층이다. 이 저장소는 ①과 ③을 이미 쓴다.

| | 지점 | 예 |
|---|---|---|
| ① | `act_observer` 교체 | `MarginMinMaxObserver` (배포 중) |
| ② | `custom_quant_annotations` | 특정 노드만 다른 비트폭·입도로 |
| ③ | 가중치 사전변환 | R3 회전(배포 중), GPTQ·AWQ·AdaRound·SpinQuant R2, Seq-MSE |
| ④ | 모델 그래프 재작성 | 임베딩 분리(배포 중) |

**하드웨어가 못 받는 것**: NF4·MX·코드북 양자화, 6비트, 활성 per-channel. 이건 코드로 못 넘는다.

미시도 카드: SpinQuant **R2**(6줄이면 되고 우리 최악 그룹 `wv`/`wo`를 겨냥한다), w4a16을 살릴
AdaRound/GPTQ. R1은 mean-subtraction 때문에 argmax가 10% 뒤집혀 폐기했다.

## 6. 타깃 쪽 상태 주의

타깃 격자 해상도 4축(캘리브 크기·KV 비트폭·가중치 비트폭·SQNR 혼합정밀도) 실험은 전부 "무효과"로
나왔으나 **그 측정은 `input_pos` 미기록 버그로 무효화됐다** — prefill 그래프의 모든 행이
position 0으로 RoPE되고 있었다. 수정 후 전면 재측정은 아직 안 했다. 타깃 양자화 결론을 인용할 때
반드시 확인할 것.

**SQNR 해석 함정**: 분석기의 SQNR은 완전 양자화 그래프에서 종단 측정돼 오차가 앞으로 전파되므로
**깊이와 교란**된다. 깊은 그룹의 낮은 점수는 상류 취약 그룹 탓일 수 있다. 같은 깊이 대역 안에서는
`w2`/`wv`/`wo`가 `w1`/`w3`/`wq`/`wk`와 일관되게 갈린다.

## 7. 방법론 — 이 프로젝트에서 반복된 오진

- **지표가 무엇을 재는지 먼저 확인할 것.** 로짓 cosine은 이 모델에서 바닥이 0.685~0.905다(서로
  다른 토큰을 예측하는 fp32 행끼리도). 0.82를 "괜찮다"고 읽어 몇 시간을 날렸다. **top-1 일치가
  AL을 따라가는 유일한 지표였다.**
- **손상은 성분으로 쪼개서 격리할 것.** 클리핑/반올림 분리 실험 한 번이 관찰자 스윕 전체보다
  정보량이 많았다.
- **가짜양자화 스윕은 export 전에 돌릴 것**(`scripts/sweep_draft_bits.py`). 다만 이건 가중치만
  보므로 활성·KV까지 포함한 실제 파이프라인과는 다르다 — 8비트 가중치 예측 0.9997 대 실제 0.889.
